# Estruturas de Dados — Prova 2 FATEC

## Porque sofrer faz parte do aprendizado

Implementação _artesanal_ de Tipos Abstratos de Dados (TADs) em Python, sem recorrer a 
atalhos convenientes da linguagem para fazer o trabalho pesado por nós.

Afinal, a proposta é __aprender como as estruturas de dados funcionam__, e não invocar 
uma biblioteca, observar o milagre acontecer e colocar no currículo que domina a ciência 
da computação.

Usar `collections`, `list` ou outras abstrações prontas para implementar um TAD em uma 
atividade didática é como contratar alguém para fazer flexões no seu lugar e, depois, 
comemorar o ganho de massa muscular. O resultado pode até aparecer, mas o mérito intelectual 
foi sepultado sem direito a velório.

Este projeto é uma tentativa deliberada de entender o que acontece por baixo do capô: nós, 
referências, ponteiros lógicos, operações, percursos e todas aquelas pequenas decisões que 
as abstrações prontas escondem para que ninguém precise sofrer desnecessariamente.

Aqui, cada nó é construído manualmente, cada referência tem consequências e cada erro 
oferece uma oportunidade de aprendizado — geralmente acompanhada de uma mensagem de exceção 
e alguns minutos de questionamento existencial.

### Uma nota aos devotos do *vibe coding*

Se a sua estratégia de implementação consiste em pedir para uma IA gerar o código, copiar, 
executar e declarar vitória quando não aparece uma _traceback_, parabéns: você automatizou 
o ato de não saber o que está fazendo.

Não há problema em utilizar ferramentas, bibliotecas ou IA. O problema é confundir 
__usar uma ferramenta__ com __compreender aquilo que ela faz__.

Abstrações são excelentes. Foram criadas justamente para que não precisássemos reinventar 
a roda a cada projeto. Mas, quando o objetivo é aprender a construir a roda, importar 
`collections` e declarar a atividade concluída é uma maneira bastante eficiente de entregar 
o exercício enquanto terceiriza o aprendizado.

Este repositório segue uma filosofia simples:

> Se a finalidade é aprender a implementar uma estrutura de dados, a estrutura será 
> implementada. Se a intenção era apenas obter o resultado, talvez o enunciado tenha sido 
> interpretado com uma generosidade excessiva.

__Aviso:__ nenhum TAD foi poupado do trabalho manual durante a elaboração deste projeto. 
Eventuais bugs, por outro lado, continuam em liberdade e não demonstraram qualquer 
arrependimento.

> [!WARNING]
> Desenvolvido em sistemas Unix-like. Fazer funcionar em outros sistemas operacionais é 
> uma  _side quest_ que não está no escopo deste sofrimento acadêmico.
